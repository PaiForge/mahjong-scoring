# お問い合わせフォームのセットアップ (Resend)

お問い合わせフォーム（`/contact`）は [Resend](https://resend.com/) の API で運営のメールアドレスへメールを送ります。本ガイドでは、Resend 側のドメイン認証・API キー発行と、アプリ側の環境変数の設定手順を説明します。

認証メール（サインアップ確認・パスワードリセット）を Resend の SMTP で送る設定は別のガイド [resend-smtp-setup.md](resend-smtp-setup.md) を参照してください。送信元ドメインは両方で共用できます。

## 前提

- [Resend](https://resend.com/) アカウント
- 送信元ドメイン（`score.mahjong.help`）の DNS 設定へのアクセス権

## 1. 送信元ドメインの認証

> **他のサイトと同じ Resend アカウントで運用できます。** Resend のドメインは互いに独立したリソースで、追加時に発行される DNS レコードは追加したドメインのゾーンにだけ置くものです。既に登録済みの別ドメイン（別サイト）の設定には影響しません。Free プランでもカスタムドメインは 3 つまで登録できます。

1. [resend.com/domains](https://resend.com/domains) で **Add Domain** をクリックし、`score.mahjong.help` を追加する
   - Resend はルートドメインではなくサブドメインからの送信を推奨しています。`mahjong.help` をルートで登録して他の PaiForge アプリと共用すると、アプリ間で送信レピュテーションが混ざります
2. 表示された DNS レコード（DKIM・SPF、任意で DMARC）を `mahjong.help` の DNS プロバイダーに追加する
3. Resend で **Verify** をクリックする。DNS の伝播には数分から最大 48 時間かかることがあります

## 2. API キーの発行

> **既存の別サイト用の API キーを使い回さないこと。** 片方のデプロイ環境からキーが漏れたときに、もう片方のドメインからも送れてしまいます。

1. [resend.com/api-keys](https://resend.com/api-keys) で **Create API Key** をクリック
2. 以下で発行する:
   - **Name**: `mahjong-scoring contact` など用途が分かる名前
   - **Permission**: **Sending access**（送信のみ）
   - **Domain**: `score.mahjong.help`（このドメインからしか送れないよう限定する）
3. 表示されたキー（`re_` で始まる文字列）を控える。ダッシュボードで再表示はできません

## 3. 環境変数

Vercel（本番・プレビュー）とローカルの `.env.local` に以下を設定します。

| 変数名               | 値                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `RESEND_API_KEY`     | 手順 2 で発行したキー                                                                                                         |
| `CONTACT_TO_EMAIL`   | 問い合わせを受け取る運営のメールアドレス                                                                                      |
| `CONTACT_FROM_EMAIL` | `contact@score.mahjong.help`（手順 1 で認証したドメインのアドレス。ローカルパートは任意で、受信箱を用意する必要はありません） |

`CONTACT_FROM_EMAIL` を省略すると Resend のテスト用アドレス（`onboarding@resend.dev`）から送られます。これは Resend アカウント所有者のメールアドレス宛てにしか届かないため、ローカルで自分宛てに試すときだけ使えます。

`RESEND_API_KEY` と `CONTACT_TO_EMAIL` のどちらかが無いと、送信ボタンを押した時点でエラー（「送信に失敗しました」）になります。フォームの表示自体は環境変数が無くてもできます。

## 4. 動作確認

1. `/contact` から自分のメールアドレスを入力して送信する
2. `CONTACT_TO_EMAIL` の受信箱に `[麻雀点数計算] <件名>` のメールが届くことを確認する
3. メーラーで「返信」を押し、宛先が手順 1 で入力したメールアドレス（Reply-To）になっていることを確認する
4. [resend.com/emails](https://resend.com/emails) で配信状況を確認する

## 送信枠について

Resend の送信枠（Free プランは月 3,000 通・日 100 通）は**アカウント単位**で、登録したすべてのドメインの合算です。問い合わせフォームの量なら問題になりませんが、認証メールも同じアカウントの SMTP 経由にしている場合はその通数も同じ枠を使います。アプリ側では 1 つの IP から 1 分に 3 回までに制限しています（`src/lib/rate-limit-ip.ts` の `contact`）。

## トラブルシューティング

| 問題                       | 考えられる原因                                         | 解決策                                                               |
| -------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------- |
| 送信ボタンでエラーになる   | `RESEND_API_KEY` / `CONTACT_TO_EMAIL` が未設定         | 環境変数を設定してデプロイし直す（サーバーログに理由が出ます）       |
| 同上                       | API キーのドメイン制限と `CONTACT_FROM_EMAIL` の不一致 | キーの Domain を送信元ドメインに合わせるか、制限なしのキーを発行する |
| "Invalid sender" / 403     | 送信元ドメインが未認証                                 | resend.com/domains で認証状況を確認する                              |
| 届かない（エラーは出ない） | `CONTACT_TO_EMAIL` の誤り、または迷惑メール振り分け    | resend.com/emails で配信状況と宛先を確認する                         |
